# Trained strategy cutover

Production recommendation ports now retire the legacy single, combination and
dual-research publishers. The normal league-trained lane remains the only
registered team-baseline producer. The existing paper lane still requires its
own approved model and exact committed forecast. Neither lane becomes formally
calibrated by this product cutover.

The live center has an explicit `trained-strategy-switch-v1` envelope. It cannot
contain legacy current rows, previews or combinations. Historical decisions,
frozen combination bindings, original scores, result events and review
denominators remain untouched. The previous daily bulletin is archive-only:
it cannot create new picks, combos or late acknowledgements after cutover.

List and detail pages require exact ordered team IDs and event time for trained
records. Open events cannot fall back to a legacy review record. Missing league
parameters, identity mapping or a valid prospective adoption record produces a
pending state, never an old model pick disguised as a new one.

This document describes the candidate code. A signed release and fresh public
projection must prove the switch is actually installed. Registration alone is
not a live forecast, and an empty new-model list is not adoption evidence.

installed SQL constraint permits only publish/combos/settlement/view; no schema
migration is needed. Model load failures remain errors. The separate old paper
producer is retired on this path. Disposable SQL verifiers explicitly retain
legacy compatibility exercises and additionally check the production cutover.
