# 净胜球驱动的让球分析

## 业务规则

普通胜平负首选不直接映射为让球方向。设主队实际净胜球 D、带符号主队让球 h，三项按 D+h 与0的大小关系确定。主队-1：赢1球为让平，赢2球以上为让胜，平/负为让负；主队-2：恰赢2球为让平；主队+1：恰输1球为让平。全场90分钟加伤停补时，不含加时与点球大战。仅处理整数三项让球，不处理亚洲半球/四分之一球结算。

## 模型

1. 读取同一轮已发布的完整HAD概率与 `probabilityModel.calculationTrace.poisson.lambdas`。目前使用的是现有计算记录公开的进球参数，可能已被上游保留两位小数；这是进球形状近似，不是重新训练或宣称校准成功。
2. 生成有尾部误差上界的自适应Poisson比分分布，不把前三/前十二比分重新归一化当作全部比赛结果。
3. 在主胜/平/客胜各组内部保留相对比分形状，将各组总质量对齐当前HAD概率。公式：P_new(score)=P_shape(score) * P_HAD(outcome)/P_shape(outcome)。因而单场胜平负的三项概率与唯一首选不被改变。
4. 对净胜球聚合，让胜/让平/让负的完整概率各取对应区域之和。让球首选取三项完整概率的唯一最大值，平手不任意选方向。
5. 另外保留“在普通首选成立前提下”的条件分布，只用来解释赢球幅度；不把条件概率冒充整体命中率。主胜概率最高，并不必然意味着让平或让胜概率最高。

模块 `handicapMargin.cjs` 也可接受明确完整的比分分布用于验证；生产适配器目前只使用现有同轮进球参数，不使用稀疏展示列表。

## 接线与记录

当前轮输入适配器保留让球线、让球数据时间、模型进球参数。`makeDecision` 生成可选 `handicapAnalysis`，其内容纳入新的输入hash与不可变decisionId；盘口或进球形状改变会追加新版本，旧版本不回写。没有参数或盘口过期时仅本组件显示不可用，不阻止HAD和现有串关。

新组件在统一推荐中心的单场卡片展示主队有符号盘口、让球唯一首选、三项完整概率、结果条件及条件分布。复盘沿用同一官方赛果事件，按保存的让球线独立判定命中；官方更正会更新复盘结果，但不改原始方向。旧记录不补造让球分析。

**本次不自动将HHAD加入2串1/3串1，不借用HAD报价当让球SP。** 让球分析 `odds=null`、`comboEligible=false`。保留现有2串>=2.50、3串>=5.00及HAD选向。此版本展示并逐场复盘让球判断，不新建HHAD组合或累计下注收益指标。

## 边界与上线

无新数据库迁移或付费接口。需同步更新当前输入适配器、推荐服务和前端，之后的新决策才带本组件。未修改模型权重、源站访问规则、鉴权或既有冻结方向。

新增测试覆盖正负整数盘口、恰赢/输球数、主胜但让负概率更高、条件与无条件区别、比分尾部、概率守恒、镜像、缺失值、版本变化、官方更正和前端契约。新增原生PG断言覆盖可选分析的保存、冻结引用、赛果更正。

本地148项指定推荐回归通过；原生PostgreSQL和完整应用构建以本提交对应CI结果为准。新方法尚未经过真实冻结样本时间前推检验，不声称命中率提升。
