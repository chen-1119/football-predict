# 结果时钟准入与候选版本隔离

## 已复现的问题

2026-09-07，在实际 `resultObservationForMatch` 入口提供 `2026-02-29T14:00:00Z`，旧逻辑自动改为 `2026-03-01T14:00:00.000Z`，并返回 promotionEligible=true。2026年没有2月29日。相同非法决策时间也能进入时间线。这是合成复现，不是发现生产已有此类记录的声明。

## 本次改动

- 共用 strictInstant 校验：只接受明确时区和合法日历字段，拒绝不存在日期、24:00、非法时区、无时区/日期字符串、布尔值和数字；合法原始字符串字节保持不变。
- matchLifecycle 的时间规范化先校验再转 UTC；避免原始坏时钟在生成结果来源凭据时被掩盖。
- as-of 时间线在学习之前拒绝坏结果时钟；明确存在但非法的决策时钟不回退到更晚的截止/开赛时间。真实 Elo 和近期状态回归证实无效赛果不会更新模型、对应有效赛果仍可更新。
- 近期证据展示复用同一解析器，不改变其合法 selectionHash 内容。
- 候选实现承诺新增 result-input-timeline，绑定严格解析、时间线及结果凭据构造的实际函数源码，规范化 CRLF/LF。原概率计算哈希不变。新规则产生新候选修订号；截止捕获拒绝缺失/变化的时间线承诺，已有 worker 重新冻结路径识别该差异。旧账本保留，不将修复前后样本合并凑门槛。

此承诺覆盖本次变动的时间线依赖，不代表整个模型全部间接依赖已经纳入实现承诺；完整Q5仍须逐项审计。未全局替换仓库所有 Date.parse，也未改变模型权重、历史方向、比分或晋级门槛。此修改不在已经签名的r699中。
