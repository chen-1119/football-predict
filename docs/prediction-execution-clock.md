# 实际执行时钟记录与完整输出重放

## 修复边界

上一轮留存输入可以重放 34 次计算的数值与选择，但完整对象仍 0/34 一致。差异涉及模型生成时间、输入回执、动态 freshness 字段、内部方向审计和 externalMarket.cutoffAt。问题是计算期间分散读取当前时间，不能仅凭相同 JSON 输入复现原输出。

本次没有把真实执行时间改成一个固定时间，也没有从对照中删除差异字段。新 `predictionExecutionClock.cjs` 在顶层同步预测期间记录**每次实际本地时钟读取**的操作类型和毫秒值。模型生成时间、计算回执、候选外部证据检查和计算中的发布资格分析使用这些读取。真实运行仍返回当时的系统时间；只有显式离线 replay 接口消费原记录。

真正的采集接收时间、最终公开发布/冻结/截止门禁、文件落盘时间仍使用原真实时钟，不被这条计算重放通道控制。`Date` 全局对象未被实现替换。时钟记录只证明本地执行顺序，不是独立来源认证，始终 sourceVerified=false。

## 实现与拒绝规则

- `predictionSet` 与无官方赔率计算器的顶层调用建立同步上下文；内部嵌套计算共享记录，异常后立即恢复。异步回调拒绝，单次最多 256 个时钟事件。
- 模型携带私有 `executionClock`：固定版本、明确 scope、事件列表及内容哈希。公开详情规范化器剔除该字段，执行输入留存保留它。
- `replayPredictionWithClock` 必须显式传入完整合法记录；缺失（包括 undefined）、哈希不符、非法时刻/权限声明、操作顺序改变、事件不足或剩余事件均拒绝，不回退到当前时间，不补造旧记录。
- 默认预测不能从用户输入中的历史字段自动启用重放。重放接口只是离线计算，不提交公开记录或账本，不取得历史来源观测权限。
- 模型身份升级为统一 v75、基础 v11；无官方赔率基础 v4、最终 `model-only-unified-v67`。此前 v3 是内部基础版本，外层原本仍为 v66，本次一并更新最终身份，不把新结果混进旧版本成绩。
- 研究工具的实现哈希清单加入新时钟依赖。将来签名包的创建/验包都要求时钟模块和验证器，实际 production-readiness 执行新的完整输出验证器。

## 验证结果与限制

14 项时钟测试覆盖 HAD、HHAD、无赔率完整输出、真实读取范围、不改全局 Date、禁止重放额外系统时钟读取、缺记录、哈希/顺序/长度/时刻/权限错误、上下文恢复、嵌套和异步限制。71 项发布合同正反例通过，实际门禁拒绝少测、忽略字段、请求真实 provider、生产写入或失败退出状态。

既有 22 捕获、20 输入算术与私有详情隐藏、16 赛事分类、46 公开参考、22 冻结版本、截止归档和 27 候选签名转换回归通过，定向 ESLint 和 diff 检查通过。本轮不改 UI，不回算历史方向/成绩，不扩大晋级资格。

34 次完整重放是在同一已加载本地实现和状态下完成，**尚未证明跨进程/跨 Node 版本或跨部署环境一致，也未完整绑定所有已加载依赖**。下一步仍需依赖身份/长期存储治理、固定同组模型对照、独立前瞻质量和新版全量工件/生产验收。

本次无生产部署，不改 r702 已签源码/包/单次队列；本补丁不在 r702 内，不能把合并和局部测试当成全目标完成。
