# 轻量发布进度查询

用途：正在发布时查询原任务，不把每次“看进度”变成一次完整发布验收。

```powershell
npm.cmd run release:progress -- --sha <本次发布包的完整SHA256>
```

沿用 `release:status` 的主机、用户、SSH 密钥和明确主机指纹配置；不接受未固定的主机密钥。
SHA 必须显式提供，不根据最近文件或其他任务猜测要查询的发布。

## 查询范围

- 一次固定 SSH 请求，无观察重试、无自动部署、无恢复操作。
- 只读取固定事务状态、双版本标记、恢复标记、服务状态和 `/proc`。
- 发布日志只读取末尾最多 65,536 字节。状态文件最多 4 KiB，单个版本标记最多 128 字节。
- 输出最后识别到的阶段、最近检查/数据库步骤的已记录耗时、事务总耗时及实际存活的发布 PID。
- 不输出原始日志、命令参数、访问凭据或业务数据；不估算假进度百分比。
- 不解包，不扫描整个工作区，不运行模型、数据库导出或任何静态验证。

阶段来自最后识别到的日志事件，不是后台作业调度器。截断窗口内没有认识的事件时返回 null，不猜测当前步骤。

## 状态语义

`observationOk=true` 只说明此次观察可用。

- `running`：同 SHA 的 running 状态，以及实际 cmdline 匹配且信号 0 确认存活的进程同时存在。
- `unconfirmed-running`：状态仍写着 running，但没有确认到对应存活进程；需要排查，不能自动重启。
- `observation-changed`：读取过程中事务状态变化，应重新观察同一任务。
- `transaction-complete`：complete/ok=1/exitCode=0、有效起止时钟、双标记一致且恢复标记清除。
- `terminal-incomplete`、`identity-conflict`、`failed`、`not-found` 分别显示，不借旧版在线或锁文件冒充成功。

即使事务完成，`liveAcceptanceProven` 始终为 false：数据库同代际、新 worker 完整周期、冻结记录、受保护路由和真实页面仍按原验收执行。
观察超时或失败也不能作为重发包、重启任务或清除恢复标记的依据。

## 验证与实测

`npm.cmd run verify:release-progress` 覆盖 21 组行为，包括假 running、失效 PID、错误 SHA、状态竞态、缺失完成标记、非零退出、恢复未结束、未来/倒置时钟、日志脱敏和受限读取。
序列化采集器在只提供读取、systemctl show、信号 0 检查能力的环境里运行；验证读取上限及文件描述符全部关闭。
实现、CLI 和验证器加入两处签名包必需项；行为测试加入签名前合同检查。
