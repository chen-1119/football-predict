## 可复现问题

签名前的 `frontendRuntimeBoundary` 已有解析缓存，但缓存键仅绑定当前模块、包配置及解析策略。若 `require('./module')` 原先解析为 `module.js`，随后候选树新增优先级更高的 `module.cjs`，缓存会继续使用旧目标，漏掉新目标引入的 UI 代码。新增真实文件夹回归先在修复前复现：应拒绝的检查返回 true。失败原始输出保留于 `outputs/runtime-cache-before-fix.stderr`。

## 修改

- 命中解析缓存时，依据当前已认证清单重新解析每条本地依赖路径；目标变化时重新解析模块，不复用旧路径。
- 保持每次调用的文件字节哈希、文件类型、链接、目录和包锁校验。未缓存文件可信状态或整项验收结论。
- 缓存仍最多保留 512 项，改为淘汰最久未使用的一项；避免达到容量时整批清空并重复解析经常使用的基线模块。
- 回归包含新增高优先级文件、路径恢复后的回退、合法目标变更，以及冷缓存/热缓存完整证据一致；原有篡改、硬链接、目录链接、执行入口和动态加载拒绝测试保留。
