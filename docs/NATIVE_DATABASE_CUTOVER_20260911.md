# 原生发布的数据库切换原语

本批增加 `scripts/nativeDatabaseCutover.cjs`。它只接受已有 v4 恢复合约，在同一 PostgreSQL 事务中将旧 `football` 改名为保留库、将独立候选库改名为 `football`。数据库集群标识、两个数据库 OID、所有者、连接和 prepared transaction 均在操作前检查；旧库保留且关闭连接，新库开放连接。不删除数据库，不复制或恢复旧数据，不强制断开连接，不修改服务或环境。

这不是可调用的生产发布入口，也不构成迁移授权。后续签名发布器仍必须先验证已接受的兼容整包、完整数据一致性、冻结/推荐证据、持久化 v4 恢复日志以及写者已停止，再使用该原语。`nativeReleaseJournal.BOOTSTRAP_SHA` 仍为空，首次线上切换仍拒绝。原有主工作区和本次正在准备的整包源码没有改动。

## 真实验证

`outputs/native-database-cutover-result.json`：独立 Windows PostgreSQL 16.15 的 8 项真实数据库测试通过。

- 错误集群、错误候选 OID 均不修改数据库。
- 应用库或候选库还有连接时拒绝，原连接保持可用。
- 第一或第二次真实改名后注入异常，事务回滚全部数据库名字和连接标志，原始中文及换行载荷保留。
- 正常切换后 OID 与合约一致，旧库仍在，新库可继续追加数据；重复调用拒绝，不将新数据倒退。
- COMMIT 已完成但客户端回执丢失时仍返回错误；实际 OID 显示切换已提交，后续应交给恢复器读取实际状态，不能自动重试。

测试使用随机端口、全新临时集群，并验证 loopback 地址和真实数据目录。测试集群已关闭并删除，生产写入为 0。本批不代表完整应用回滚、签名发布执行器或 PostgreSQL-only 线上切换已经验收。
