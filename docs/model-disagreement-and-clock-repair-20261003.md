# 26场分歧定位与模型输入时钟修复

## 云端QA修订：请使用v2诊断

云端真实协作指出，v1的 `metadataCompleteAtOriginalDecision` 只检查了 `latestObservedAt`，漏检摘要自己的 `resultEvidence.decisionAt`。这会把使用较晚截止时间的摘要误标为原决策时合格。该字段在原生成器中是评估截止时间，不是摘要生成时间，也不是原资料可用时间。

已上传的 `disagreement-attribution.json` v1及其SHA保持不变，供追溯；修订结果保存为 `disagreement-attribution-v2.json`。**旧101／66／7只能描述摘要计数完整，不能解释为原决策时已有资料。** v2严格检查摘要截止时间是否缺失、非法、晚于原决策，或早于摘要自己报告的最近观察时间，并使用纳秒精度。

新负例先复现了“latest较早、summary截止时间晚1纳秒仍被接受”的问题；修复后本文件对应10项定向测试通过，涵盖缺失/非法时钟、纳秒矛盾、相等及不同时区表示。原154场的78／83、26场的19／5／2、训练准入0及生产门槛均未改变。

## 恢复form之后仍缺什么

379份form对应758个队伍槽位，其中101个仅在摘要层面具备完整观察时间计数。154场配对的308槽位中为66个；26场分歧的52槽位中为7个，其余为32个观察证据不完整、8个缺证据对象、5个空样本。完整摘要也不等于取得受信任的原始逐场记录。

加入摘要截止时间检查后，以上三组仅22／2／0个槽位满足摘要计数与原决策截止时间的一致性；79／64／7个计数完整槽位使用了较晚的摘要截止时间。即使22／2／0满足这些摘要检查，仍缺受信任的原始逐场记录，**三组 `originalDecisionAvailabilityProven` 和训练准入均为0**。

已知 `latestObservedAt` 均未晚于实际冻结决策，但摘要截止时间更晚或缺失观察时间时不能据此视为原决策时合格。历史恢复提高了资料可见性，没有将这些数据自动变成可训练样本。
