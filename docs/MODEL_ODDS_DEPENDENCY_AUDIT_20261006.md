## 1. 结论与本次工作边界

用户指出“有时全部正路、有时全部下盘，推荐近似跟随赔率，缺少比赛特定依据”。实际代码及线上冻结回执支持需要修正这一问题，但根因比“全部概率直接取赔率倒数”更具体：

1. 现有概率确实使用球队历史、Elo、近期进球率和Poisson，但同时混入市场概率与人工先验，不能称为赔率独立模型。
2. 三场输入处于冷启动，通用均势先验占较大权重；五场公共模型回执实际触发了“国际赛热门低SP统一减5个百分点”。这些机制会系统性压低热门，不能替代针对每场的伤停、阵容或攻防证据。
3. 旧选择器跨市场直接比较最大概率，七场全部选中受让保护事件，再为其选条件胜平负分支。概率覆盖较广不是价值优势；两个方向在原始模型概率下已经是负EV。
4. V2已经调整了方向和展示关系，但保留了原模型概率。本次没有完成赔率独立模型训练，没有证明命中率提高。
5. 七场真实冻结数据均没有接入可用xG、伤停或首发，不能编写这些信息作为推荐依据。Poisson进球率不是实测xG。

本文件是审计与实施要求。本次只编辑本文件；模型生成代码、线上数据库、旧冻结推荐、23:16影子版本均未因本审计修改。同步进行的界面纠错属于另一个变更，不能表示本文件中的新模型已实施。

## 5. 七场真实数据缺口与证据标签问题

核查对象是最新七条公共参考记录的完整 `probabilityModel`，不是仅从平台投影缺字段就推断缺数据：

| 特征 | 七场实际记录 | 含义 |
|---|---|---|
| 历史观测xG／赛前xG信号 | `connected.xg=false`，7/7 | 没有可用观测xG参与此次比较 |
| xG联合拟合 | `lambdaBlend.jointGoalFit=null`，7/7 | 实际没有执行这一拟合 |
| 伤停 | `connected.injuries=false`，7/7 | 不能声称依据主力伤缺推荐 |

| 裁判、球队牌数、webConsensus | 对应connected均false，7/7 | 未形成可用本场证据 |

当前缺失xG被一些质量字段标记为“尚未到正常发布时间”，但历史观测xG与当前场次赛后xG应分开管理。历史xG的缺口不能通过等待本场开赛补足为赛前特征。本场赛后xG只能用于之后比赛或模型研究，不得补进已冻结本场推荐。

001/005/006尽管只有1至2场历史，`preMatchQuality.components.strength/form.status`仍为verified，总质量为65。原因是 `scripts/syncFreeFootballSignals.cjs:124`只检查两边历史>0，145行只检查两边Form>0；`scripts/syncPreMatchSignals.cjs:560`与570行据此赋verified分数。这是“有字段/有历史”与“样本足够、赛前可审计”混淆。

另外，大样本四场的12条Form中部分记录缺逐条来源及观测时钟，存在 `resultEvidence.sourceVerified=false`、`temporalStatus=unverified`；总体签名训练文件和算术回放通过，不能替代逐条时间来源证明。平台输入回执的 `arithmetic.scope=base-calculation-only`、`sourceVerified=false`也没有声称供应商事实已验证。

强度、Poisson或Form不能全部标为独立verified证据。下一版需要分别表达来源存在、时序可用、样本充分、实际采用、模型校准状态。

## 6. 尚未实施的下一版：三条轨道

### 6.1 赔率独立球队模型 `p_team`

1. 输入包括赛前可审计历史比赛、对手强度、主客场、时间衰减、赛程密度、历史射门/观测xG、经来源与时钟验证的阵容和伤停。
2. 每条输入必须有球队/事件身份、观测及可知时钟、来源、版本、缺失状态。后续出现的数据不能改写原预测特征。
3. 全因果路径禁止赔率、盘口、去水概率、基于赔率的上下文/质量/冷却、由赔率派生的先验、标签或拟合目标。仅删除最终权重中的market项不足以满足零赔率要求。
4. 由同一经验证的goal distribution聚合HAD、整数HHAD、比分和进球数；若goal模型不适用，明确无输出或单独定义模型，不能强行对齐方向。
5. 冷启动或身份/时序不足返回不可推荐状态；保留内部诊断，不输出伪精度。

### 6.2 市场基线 `p_market`

使用同一可知截止时间的真实报价，保留源、盘口和时钟，计算去水分布作为独立基线。若将市场与球队模型混合，则另命名 `p_hybrid`，不得称赔率独立；权重必须在历史时间切分中估计并独立验证。

“三个市场概率加起来100%”只是归一化。任一方向的最大概率都不是100%命中保证。

### 6.3 校准后的决策层

只有在样本、时序、校准和正式登记准入通过后，使用校准 `p_team`及不确定性、同钟SP和市场基线审查方向及价格。对候选评估经校准净收益、风险与覆盖，不跨市场裸p选主。

未验证的冷却仅改变观察、暂停或风险状态，不重写p。正路、下盘和冷门分布由逐场真实信息及价格产生，不设比例配额，不为凑串关降低准入。

逐场说明必须列出具体比赛事实、源和时点、贡献或敏感性、缺口、与市场差异及是否行动。没有足够特定证据时写“观察/不推荐”，不能用叙述模版补事实。

| 数据质量 | 样本充分、独立来源族、来源时钟及缺失原因分别可查；市场接入不增加球队独立证据数量 |
| 消融比较 | market-only、team-only、现有hybrid、无手写热门扣减/冷却版本同时运行；每项输入族另做删除/加入比较 |
| 时间切分 | 按独立比赛日顺序训练、校准、验证；同一比赛不同发布版本不得跨训练和验证集合，赛后资料不得泄漏 |
| 概率评估 | 各独立日报告多分类Brier、log loss及分档校准；比较基线增量与区间，不能仅看当天最大命中率 |
| 行动评估 | 预先固定选择规则后比较推荐覆盖率、HAD/HHAD各自命中、同钟SP收益、回撤、尾部风险；有概率输出不自动成为行动 |
| 分组稳健性 | 冷启动/充分历史、国家队/俱乐部、热门/非热门、盘口幅度及报价来源分组；披露不足组，不选择表现最好组推广到全部 |
| 正式晋级 | 继续遵守现有校准注册、独立时间窗口和发布规则；一次七场结果不能降低门槛或宣布模型胜出 |
| 冻结连续性 | 旧decision、公共参考、串关、比分首项、影子manifest hash不变；Top3单独复盘，不能替换旧首项命中分母 |

七场只作为已冻结的前瞻研究记录进行赛果核对，不能训练后回填为“赛前改进”，不能凭一晚证明命中率或收益提升。正式结果未确认时保持待赛果，不把缺结果视为0-0或未命中。
