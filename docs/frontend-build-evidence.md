# 前端构建证据的边界

`frontendBuildEvidence.cjs` 执行并记录现有的三步前端构建，不是签名器或部署入口。不能用一个 `ok`、已有 `dist`、本地构建成功或这份证据替代生产验收。

## 已实现

- 固定 `tsc -b`、`vite build`、`stripLargeStaticPayloads.cjs` 三条实际 Node 命令及完整成功退出状态；拒绝其他 build 字符串和 pre/postbuild 生命周期钩子。
- 构建根必须独立。`dist` 必须不存在或为空，旧版产物/基线应放在构建根外；两类缓存目录只接受明确的输出，不允许旧编译缓存参与本次构建。
- 输入范围包括完整源码、生成数据以及实际安装的全部依赖，不用锁文件存在来冒充依赖字节相同。限制文件/总量，稳定句柄哈希，比较执行前后成员及字节/模式。
- 固定构建环境，去除继承注入器；共享 300 秒默认 deadline，最大 600 秒；失败保留有界输出和准确失败命令，不能把失败重新解释为缓存命中。
- 验证基线与候选 dist 清单的字段、唯一有序路径、数量、字节总量和 treeHash。证据绑定基线原包 SHA、dist treeHash、完整清单哈希，而不只绑定旧 index。
- 候选仅可改变 `index.html` 和内容哈希命名的 assets。已有资产同名不同字节拒绝；旧资源从新构建中消失时仍明确要求生产保留，永不产生删除列表。其他 dist 文件改变必须走完整发布。

## 明确不由本模块证明

普通 `spawnSync` 只等待直接子进程，不约束外部文件、网络权限或脱离的后代。因此它返回 `executionAssurance=unsandboxed-direct-children-only`、`signingEligible=false`、`descendantsQuiescent=null`，生产写入和供应商请求数为未知，不能虚报为零。Windows 的私有根检查也不是 ACL 隔离证明。

基线参数虽然严格验证结构并绑定哈希，但仍未认证。Linux 专用构建控制器必须另外执行隔离单元、约束输入/写入/网络并证明 cgroup 清空；可信发布入口还必须核验原始签名基线、实际运行版本、前端运行时边界与目标页面/资产 CAS，才可授权原子切换。

## 验证口径

`verifyFrontendBuildEvidence.cjs` 的 17 项是受控合成编译器测试，实际运行三个 Node 子进程，但明确不是 Vite 编译证明。真实 Vite 构建另存输出记录，不能把合成测试、真实构建、隔离构建、签名包和线上完成混称为一个成功状态。

真实 Linux npm 安装揭示了合法的嵌套 `.bin`：现在仅允许 `node_modules/(package/node_modules)*/.bin/name`，package 可含单个 npm scope；最终目标仍须属于同一依赖根的普通单链接文件，禁止任何隐藏/缓存目录、源码和逃逸路径。新增正/反向验证，不把规则放宽成允许任意链接。

源码及相关策略变化会使旧构建证据失效。后续接入只重做受影响的步骤；纯证据验证不应派生新的生产部署。
