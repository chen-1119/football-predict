# r688 优化实施与验收

顺序：推荐记录一致性 → 刷新与补充源 → 数据口径 → 影子验证 → UI。

- 推荐：页面公开参考与内部候选分离；同一官方赛事 ID、开赛时间、截止时间绑定公开方向，来源切换不得重新选择。历史冲突保留证据，不依据赛果改写。
- 刷新：写锁期间保留完整旧代际并自动重查；所有入口遵守写屏障，验证 PG/SQLite 四字段一致后才切换。
- 补充源：保留请求限额；记录可脱敏的 DNS/连接/TLS/超时原因，不将网络失败误判为账号停用。球队映射未验证不采用。
- 数据：null/空字符串不等于 0；近期状态显示时效与缺失，避免把同一历史来源重复计为独立证据。
- 模型：新逻辑仅作影子对照，保留现有登记账本与独立窗口门槛；不承诺命中率提升。
- 页面：紧凑比赛布局、清晰方向与时间、两列证据事实、可展开的数据缺口；桌面和手机无横向溢出。

验收：行为回归、TypeScript 构建、真实页面桌面/手机检查；合并发布还需签名包和线上版本、数据库、采集周期证据。
