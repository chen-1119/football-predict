# 命中率优化与混合玩法串关

## 已知起点

9月21日的线上只读审计中，新统一推荐共有69场不同比赛，43场完成结算，21场命中（48.8%），另有26场待结算。独立让球完成15场，命中7场；2串1、3串1仅分别完成2组、1组。所有推荐仍为未完成模型验证的参考数据。

同一批43场的市场最大概率方向也命中21场，模型Brier约0.6205、市场概率Brier约0.5974（越低越好）。这些结果不支持“已稳定提高命中率”的结论，更不能通过选择性删除未命中记录获得提升。

## 本轮实现

1. 从最终胜平负概率校正比分矩阵的主胜、平局、客胜区域，再由同一矩阵生成独立让球概率和条件伴随概率。独立让球用于串关候选，条件伴随只解释“主方向成立以后如何赢盘”。
2. 保留PR37的条件方向展示，修复旧v1历史解释。新版概率算法、v1/v2/v3让球记录分版本复盘；条件样本与全样本不共用一个分母。
3. 2串1、3串1允许胜平负与让球胜平负混合。每场只选一个玩法；不重复比赛、不重复球队；继续要求总SP分别不低于2.5、5。
4. 让球候选必须有真实、新鲜的竞彩网HHAD三项SP、明确整数盘口、比赛绑定和赛前时间。选择独立让球概率最高方向，不使用伴随条件占比替代无条件概率。没有满足条件的数据，就不添加这一玩法。
5. 串关保存原不可变单场决策，再单独冻结玩法、盘口、方向、SP、报价时间和哈希绑定。赔率计算、截止检查、页面与赛果结算均使用这份选择；历史组合原样保留。
6. 前端逐条显示玩法和盘口，明确混合组合的参考状态，不将单场概率相乘的排序分数包装成经过验证的组合命中率。
7. `qualityReport.cjs` 评估每场截止前最后发布的冻结预测，输出按比赛日、概率区间、同场市场基线和95%命中率区间。它不训练、不修改生产数据，也不会自动晋级模型。

## 命中率验收路线

先完整回补可验证赛果，保留缺失、作废和争议状态；此前26场待结算不能被当成失败或成功。对于联赛官方参考赛果，继续保留其原有正式晋级限制。

随后按独立竞彩日滚动积累新版冻结样本，比较同场市场Brier、LogLoss、命中率和覆盖率。质量报告初步证据门槛为至少100场已结算、7个独立比赛日，并同时优于同场市场Brier和LogLoss；满足这些只是进入进一步评审，不能自动变成正式模型，也不保证以后表现。

不依据本轮看到的7场主让1结果强制指定让平或让胜，不依据8场高概率样本事后设置有利筛选阈值。筛选或校准参数修改须在后续独立比赛日验证，并保留全量、入选、未入选三个样本组。

## 验证与上线边界

- 单元回归覆盖条件概率与独立概率隔离、整数盘口、真实SP、去重、过期报价、选择篡改和旧版本冻结兼容。
- PostgreSQL集成测试使用独立一次性测试schema，验证混合组合写入、原HAD决策绑定、盘口结算、并发和冻结不可变；不把测试数据写入生产。
- 部署前完成完整构建与CI。部署后核对新运行版本、原台账哈希、API及页面所显示的玩法与SP。
- 若当天无合格HHAD报价或不足组合场次，展示明确原因；不能用模拟组合声称已经产生真实线上混合推荐。

下一步仍需修复待结算数据缺口、今日SP覆盖，并在足够的独立比赛日上检查模型表现。这些工作与增加让球玩法分开验收。
