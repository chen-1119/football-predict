## 修复的证据缺口

整份文件首次下载时可能有当天或未来比分。当文件后来被重复下载，只有新的真实接收记录满足日期和行校验时，才能说该赛果在本研究存储中被有效观察。不能用文件的旧 firstObservedAt，也不能仅因为查询时间已经过了几天就让旧的隔离比分变成历史可用结果。

新增只读命令：

```text
npm.cmd run research:openfootball-result-receipts -- <绝对私有研究目录> <明确ISO截至时间>
npm.cmd run verify:openfootball-result-receipts
```

新模块复用既有 SQLite 原始响应和连续接收链。一个只读事务先核验完整存储，再严格按实际 receivedAt 不晚于指定截止时间的记录重放；按每次真实接收时间重做行准入，不重新抓取、不写数据库、不用查询时间重分类。只读事务拒绝任何写操作。

每个来源事件及比分修订保留 firstQualifyingReceiptAt、首次和最近 receiptHash、原文件 SHA、原始行 SHA、接收序号及实际次数。不同比分保留多个修订并标记冲突，不擅自选一个；恢复旧比分也不能抹掉已知冲突。最新来源删除比分、删除事件或出现重复身份时，保留旧证据但标记 withdrawn-or-quarantined。纯非比分元数据变化保留新行证明，不误报为比分冲突。

截至时间索引散列只绑定当时的接收前缀和研究结果，未来追加不改变过去索引。完整存储审计单独列出，允许反映后来的链头。重放限制累计 128 MiB 原始响应字节、最多 50000 个修订；超限明确失败，不截断后假装完整，也不删除旧接收记录。

限制：这些仍是未核准映射、非官方的社区研究结果。sourceEventId 由赛季、联赛、日期、原始主客名称构成，不是独立提供商永久赛事 ID；上游改名或改比赛日期可能形成不同身份，不能据此宣布所有跨版本身份冲突已解决。没有伪造开球时间、上游发布时间、独立见证或过去决策证据。resultObservedAt 仅在当前研究状态无冲突且最新来源仍含合格候选时提供；仍必须另查来源时效、实体映射、模型采用和正式准入。
