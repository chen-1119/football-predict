# 串关为空：数据版本竞态和前端误隐藏修复

## 可复现的错误

基准提交 ff09a1c01535c2900f2f2c4fdf2906e56854bf7d。

1. 单场发布与串关生成使用独立事务。当两步之间源数据更新时，串关按新输入生成decisionId，却只查找上一个事务已保存的ID；新ID都不存在，候选全部被过滤掉。
2. 页面根据publish任务状态和它的输入时间决定是否显示串关。即使combos任务成功，单场任务失败或时间较旧也会隐藏两种即时组合。

这两项是代码和构造回归可复现的问题，不代表已经读取生产数据库或穷尽线上空组合的全部原因。

## 修复

- 单场和串关共用bindCurrentDecisions。串关从自己的事务快照读取有效输入；缺少的同一决策记录在该事务中幂等写入并读回核验，然后组串。不会使用旧方向填充新行情，也不要求旧BEST/正式单场资格先通过。
- 重复输入复用已有记录及其原发布时间，不覆盖旧冻结记录。单条写入失败使用保存点隔离；全部写入失败报告真实错误，不返回“成功但0候选”。
- 前端按combos任务自己的状态、输入截至时间、成功时间判断即时组合可用性，不再依赖publish任务。每腿仍检查报价时效和停售时间。
- 可用场次数和串关输入时间传到页面。数据更新中、有效场次不足、SP约束未满足、无历史复盘分别显示，不统一伪装成“不推荐”。

2串1原始SP>=2.50、3串1原始SP>=5.00不变；同场/共享球队去重不变；唯一首选与组合排名算法不变；赛果更正、不可变台账、鉴权与历史统计不改。本轮无需新迁移、新定时器或重新初始化数据库。
