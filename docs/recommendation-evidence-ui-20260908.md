# 推荐证据与页面改版 · 2026-09-08

本批是推荐证据展示与页面结构修复，不是新模型晋级，也不代表线上命中率提高。完整发布和后续 UI-only 发布分别验收，代码合并不等于上线。

## 改动内容

- 修复近期状态的计算来源在前端投影时丢失：区分训练历史、500 近期状态、两者混合、真实空输入和来源未记录。
- 推荐卡常显「依据与限制」：决策时间、具名基础计算记录、缺失与未核验输入。完整版本、回执、样本和采集诊断保留折叠审计。
- 主客近期样本明确限定为训练历史，不因 500 数据参与联合计算就虚构单边训练样本。
- 候选模型补齐 14 项晋级条件展示，包括样本差额、窗口综合条件、两项校正置信下界、无效/单一证明方占比、账本与分母、激活顺序等。
- 后端未公开的逐窗明细、完整性分项和上次评审检查点继续显示待证据；单项满足不覆盖后端整体评审状态。
- 后端比例经六位小数舍入，恰好等于上限时不据此确认达标；对应后端阻断项优先，避免舍入后的误判。

## 不变的边界

只读取原公开记录绑定的计算摘要。当前采集诊断单独展示，不补写原推荐、方向、哈希或历史命中。基础计算记录不是来源真实性认证、最终推荐贡献率或采用率。空值不补作 0% / 50%，未取得伤停不解释为没有伤停。

模型数学、发布门槛、正式/参考/影子账本和原冻结方向未调整。没有新增收费数据源、投注操作或串关推荐。

## 定向验证入口

使用 Node 22 和 `npm.cmd`：

- `npm.cmd run verify:data-adoption`：冻结投影与中英文 React 展示。
- `npm.cmd run verify:data-adoption-sources`：真实内存计算 → 快照 → 冻结发布 → 来源投影。
- `npm.cmd run verify:candidate-promotion-gaps`：晋级条件、缺失值与阈值边界。

无需为这批页面回归重跑历史训练、同步上游或完整生产发布。新验证器同时列入完整归档创建与验收的必要文件清单；它们不是额外的后台任务。
