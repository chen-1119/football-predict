2026-09-08。本批为 Q2 数据证据工程，不改变推荐模型或正式结算。代码不在已签名排队的 r704 中。

## 已实现

在现有五大联赛审计适配器基础上，新增显式指定私有目录的研究采集命令：

```powershell
npm.cmd run research:collect-openfootball -- 2026-27 <绝对路径的私有研究目录>
npm.cmd run verify:openfootball-observations
```

仍限定 OpenFootball 的五个固定 URL、拒绝重定向、单源 20 秒和 2 MiB、顺序最多 5 请求、无自动重试。完整响应读取后记录真实 receivedAt，要求不早于 requestStartedAt。无法完整读取或解析的响应不作为成功记录。

独立 SQLite 研究存储保存原始字节、内容 SHA-256、来源/联赛/赛季以及连续哈希绑定的接收记录。重复内容保留本存储中首次接收时间；修改比分得到新内容记录；后来恢复旧内容也保留其原首次时间。失败不会刷新先前成功证据。写入使用事务与 FULL 同步；写入前核验全部既有接收链及内容，损坏旧记录不能继续追加。数据库类型、硬链接、文件/内容大小、记录数量及磁盘余量不满足要求时拒绝操作，不清理历史证据腾空间。

限制：firstObservedAt 是本存储首次收到整份文件的时间，不是上游发布时间、比赛结束时间、首次有效赛果时间或所有旧决策的可用性证明。此前一次性内存审计的时间不回填到新存储。同一文件可能包含尚未准入的当天/未来比分，因此不能拿整份文件首次收到时间直接替代逐赛果准入时钟。哈希链用于本地完整性检查，不是独立签名见证，也不能证明有写权限的操作者无法伪造整条链。

源依然是 `sourceVerified=false`、`entityMappingStatus=unverified`、`productionEligible=false`、`officialSettlementAllowed=false`。模块不导入模型、训练仓库、实体写入器或官方结算器。
