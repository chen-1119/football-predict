# 复盘证据面板：第一批 UI 优化

状态：2026-09-07，已增补服务端玩法分组，本地实现与合成数据浏览器验收；不代表已经部署。

## 已实现

- 在 `/review` 分开呈现正式推荐、数据参考和候选研究影子；保留原始 BEST 每日/累计统计，改为原生可键盘操作的折叠区。
- 正式和参考提供近 7 天、近 30 天、累计窗口。仅从服务端完整账本 `daily` 汇总，先对账 `cumulative`，不从分页的历史比赛列表补统计。
- 窗口包含统计生成的北京时间当日，分别回溯 6 / 29 个日历日。显示实际起止日与更新时间；历史起点晚于请求窗口时标注不足完整窗口。过时账本不会伪装为今天数据。
- 无样本不显示 0%/50%；缺失、错误日期、未来日期、重复日期、计数不一致、错误轨道/合同均保持待更新。
- v1 统计没有可核验的冻结版本分组。“本版本”显示缺口，不引用实时 `modelVersion` 或把累计冒充版本成绩。
- 服务端 `marketBreakdown / review-best-market-v1` 按已结算冻结 BEST 行分为 HAD、HHAD、UNKNOWN；原始总账不变。每个分组的日期/计数、三组总数与每一天都要与总账对账。重复冲突事件仍整体排除，缺失或不规范玩法标签不从当前赔率推断。
- 页面默认 HAD，提供 HHAD / BEST 总账切换。旧 API 没有完整分组时显示待更新，不能自动回退混合总账。赔率基准、覆盖率缺少同组证据时明确待补证，不拿其他账本/赛后赔率替代。
- 候选研究只展示其实际提供的已结算计数及版本/时间。公开候选合同没有命中数，不能由 settled 猜命中率。
- 局部中性深色、清晰数字层级、减少重复卡片；390 / 768 / 1440 自适应，长版本自动换行，折叠按钮有焦点轮廓。没有改变全站主题或改写历史推荐。

## 验证与复现

1. `npm.cmd run verify:review-dashboard`：14 组窗口/合同/实际组件行为测试，包含未知玩法显示及不并入 HAD。
2. `npm.cmd run verify:review-performance`：29 项完整账本与服务端分组回归，通过真实新组件而非常量替身。包括总数相同但各日错位的负例，不仅检查累计。
3. `npm.cmd run build`；相关 TSX/TS ESLint、40 项页面口径、7 项反向变异、37 项结算展示回归。
4. 启动 `npm.cmd run dev -- --host 127.0.0.1 --port 5197 --strictPort`，再运行 `npm.cmd run verify:review-dashboard-browser`。需要 Playwright 与 Chromium；可通过 `REVIEW_QA_PLAYWRIGHT_MODULE`、`REVIEW_QA_CHROMIUM_EXECUTABLE` 指向已有安装，不需要新增付费工具。
5. 浏览器脚本加载 `scripts/fixtures/review-ui/index.html` 的真实页面组件、合成上下文，不请求生产 API。33 个场景覆盖三宽度、空样本、HAD / HHAD / BEST 切换、参考各窗口、版本缺失、长候选版本、键盘展开、缺失数据及英文。输出在 `outputs/review-ui-browser-report.json` 与三张截图，页面明确标注合成验收。

构建仍会提示既有 `/media/worldcup-glory-hero.jpg` 没有在构建时解析；本页没有新引入此资源。大体积 JSON 的构建产物清理只处理本地生成的 dist，不删除源数据。

## 明确保留的下一批工作

1. 服务端建立经过证明的冻结模型/策略版本分组。新增 HAD / HHAD / UNKNOWN 投影需在真实生产完整账本更新后复验，不能把本地旧历史文件截至 2026-06-15（早于当前统计起点）的零样本当成线上数据。
2. 建立同一决策事件、同一市场、完整赛前赔率的配对基准与冻结候选全集覆盖率。无法证明的历史数据继续标记未知，不能追填有利赔率。
3. 在列表/详情统一展示冻结时间、实际采纳输入和缺失原因；补齐校准图及其他页面的结构整理。
4. 完整应用外壳和生产受保护页面验收，以及新的签名发布、Git 主分支集成。不能把这批本地 UI 通过当成全计划完成。

本批没有降低正式准入、替换模型、改写推荐方向或美化实际命中率。
