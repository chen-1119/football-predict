## 已实现

1. **发布序号前置检查**：验证 UI 与完整发布分支互斥、各消费一次序号且 UI 分支成功或失败后均退出。替代错误的全文件字面出现次数断言；防重放和原子消费检查保留。签包前及服务器构建前执行廉价源代码检查。
2. **验收遇错立即终止**：默认首个失败停止后续检查。已有候选监听器的发布模式，在昂贵验收子进程之前验证列表响应和原有 20,000 字节平均每行门槛。完整诊断模式只用于排障，不产生通过结果。
3. **短期验收凭据**：新增及原有验收创建的邀请码均指定 900 秒有效期；提前退出时撤销已创建凭据。此操作限于验收自身凭据。
4. **保留兼容模型产物**：比较完整后端／模型输入代码、依赖清单及版本迁移声明，只有相同模型输入、受审 Node 版本和现存非空模型产物时才保留模型。UI 与明确列出的发布工具改动可排除；未知后端文件、依赖、版本或缺失产物一律完整重算。保留分支跳过回测、策略优化及由其引起的重复导出，仍执行新鲜截止点和版本连续性检查。不提供强制跳过开关。
5. **跨发布静态结果缓存**：仅覆盖原来已审计的 3 个纯静态验证配置，不缓存实时接口、比赛数据、数据库一致性或全部验收。Linux root 私有存储、HMAC、输入及运行环境指纹、策略指纹和原检查时间共同约束复用。每个新版本仍签发绑定新包身份的 root 证明；不匹配、过期或损坏则重新执行。
6. **分步计时**：构建及候选刷新步骤记录开始、结束、退出码和真实秒数，结束时间包括子进程清理。只读进度解析显示具体步骤，不输出猜测百分比或原始私密日志。
7. **最小列表精简**：已有冻结参考记录时去除重复的数据缺口字段；精简质量组件中的冗余 key 和非必要说明。详情和完整冻结记录保持原样，未提高响应体积门槛。
