# Fixed broker installation and review revision

This change is a candidate, not an installed service or a completed cloud handover.

## Installation

The existing API authenticates operator/admin mutations before and after its bounded body read. Its fixed socket client preserves NoNewPrivileges. The root listener admits only the API unit's real MainPID, ordered UID/GID, executable, command, cgroup and invocation. It rechecks the peer after the body and after the command.

The separate installer scope is `football-research-broker-install-v1`. A fresh RSA authority lasts at most 900 seconds and binds the complete installed release, current API/worker PIDs, exact listener/peer/unit/manifest bytes, the complete pg package dependency inventory, and the isolated Python/OS program inventory. It requires the original exclusive kernel release lock. No caller can supply a program, destination, user, database or environment. It writes a distinct fixed root service and journal; it does not change the API unit's privileges or production data.

The installer must run only after a new, reviewed full source release has actually completed. Current r863 lacks these candidate source bytes and must not be repackaged or used as its install baseline. A failed or interrupted installation retains its intent and files and refuses a blind retry. Actual installed process/cgroup, runuser child lifetime, authenticated HTTP read/archive/publication/second ACK and cloud independent login still require live acceptance. Fixture callbacks and Linux CI are not that acceptance.

The listener executes only the fixed original flock + broker + unprivileged worker. A timeout exits the service; systemd KillMode=control-group ends every descendant before restart. A durable unknown mutation intent refuses automatic retry. Reads use fresh journal identities. Repeated acknowledged mutations return the original receipt bytes and original completion clock, plus a separately named delivery clock. Journal entry/byte/free-space limits are checked before command dispatch; no evidence is deleted.

Before subsequent full releases, the broker must be included in the exact accepted unit lifecycle and refreshed against that newly accepted source identity through a reviewed signed scope. An idle broker bound to an old release refuses requests. The current initializer does not authorize replacement of an existing installation. Do not widen the read-API component controller, ignore unknown processes or remove a binding to make deployment pass.

## Human-authorized review rule

The user selected append-only review versions that may adjust direction and reference scores. A single must be verified still on sale and not started, with fresh official SP and new evidence. The first qualifying version, original direction/SP/scores/signature/ACK and its settlement identity remain unchanged. Later versions settle separately and never increase independent event counts.

After kickoff, singles can only append factual/live/postmatch material. Any combo containing a started, in-play or finished event freezes the entire existing group, legs and SP. A new combo version requires every leg verified unstarted and on sale.

`researchRevisionPolicy.cjs` only computes that disposition. Durable revision storage, the revision publisher/second ACK, revision projection and UI are not implemented by this planning module. The old v3 publisher continues to reject an already frozen event. Do not relabel an original publication as a review or claim the review feature has been installed.
