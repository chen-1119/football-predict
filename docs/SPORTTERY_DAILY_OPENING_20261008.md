# 当天报价与推荐从北京时间11:00开始整理

## 用户要求与范围

本系统按用户指定的每日11:00处理当天竞彩报价。这是系统的运行策略，不代替官方逐场销售状态，也不声明全国体彩统一的法定开售时间。

- 11:00前：赛程、比赛状态、球队资料、真实赛果继续采集和更新。快采伴随请求只取完整current响应，不请求calculator。
- 11:00起：快采在单实例串行队列的下一自然轮取得current＋calculator，首轮不依赖赛果是否变化；正常worker的休眠也在11:00边界结束。
- 接到报价后：正常投影、验签、身份、销售许可、模型、发布与截止检查全部通过，才允许产生新记录。
- 11:00后官方仍暂停销售、没有报价或证据不合格：继续等待，不补造推荐或二/三串一。

11:00是开始整理的边界，不保证当天第一份推荐在11:00整完成。正在执行的采集、发布、恢复、锁及WAF退避均不被中断。完整采集或Cloudflare取得的原响应可能同时含赛程和SP；原始载荷与签名完整保存，提前报价只作参考，不能作为当天新发布的依据。

## 时间与市场身份

`sportteryOpeningPolicy.cjs`按可信竞彩业务日计算UTC03:00，使用已有纳秒时钟解析器。跨午夜比赛使用竞彩业务日，不能把第二天开球日当成新的报价业务日。

当天新候选的决策时间、原始请求时间和原始响应时间必须全部在该业务日11:00以后。10:59请求、11:00返回仍不合格；上传、合并、PG写入或重新签收时间不能替代请求时间。缺时钟、未来时钟、时序倒置均不能放行。

HAD和HHAD分别检查自己的报价证据。HHAD同时依赖current销售状态和calculator价格的两个签名采集时钟；不得借HAD补缺失的HHAD。竞彩整数让球与亚洲盘口仍是不同市场。

胜平负已取得有效新报价，而让球仍是提前价格时，新候选只移除临时输入中的整个让球报价原子，保留可验证的胜平负；输入捕获哈希绑定筛选后的实际输入，PG父记录与原始签名响应不变。新纸面记录另带固定业务日与11:00边界标识，按市场重放筛选；旧纸面记录没有该标识时继续按原合同重放。

共享mapper及最终新raw边界阻止各采集旁路把提前价格投影为当天新报价；历史已保存字段依原合并规则保留。价格、让球线和来源始终作为同一市场原子处理。

## 历史与模型

新门只放在新候选、新纸面创建及追加写入入口。旧V1/V2收据验证、历史纸面重放、已发布方向、比分首项、赛果和市场独立结算保留原合同。没有改写原时钟或重新封存已截止预测。

本次没有训练、调高概率、批准PRD模型或证明命中率提高。真实球队证据、Elo＋泊松样本外验证、分市场校准及8周前瞻CLV继续是独立的后续工作。

## 验证与发布

`npm run test:sporttery-opening`检查边界、跨11请求、缓存/上传重戳、签名新候选、两个市场、真实runCycle的合成控制流、投影旁路和休眠唤醒。旧签名发布、纸面、赛果及worker回归继续执行。新验证接入签名前检查与两份必需归档清单，不减少原发布门槛。

单元/控制流测试不证明官方已开售或生产已发布。本次线上11:11:28只读观察确认6场及签名current的真实请求03:11:02.949UTC、返回03:11:02.964UTC，逐场Selling/CBT过关许可有效；仅为该次采样事实。

新代码只有通过正常完整签名包、发布事务、实际源码/dist、PG、自然worker和逐场输入验收后，才可称上线。全仓原lint失败不重新记为通过；没有正式合资格输入时，空态不记为新模型或推荐成功。
