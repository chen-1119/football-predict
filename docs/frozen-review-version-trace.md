# 冻结版本追溯与复盘分组（2026-09-07）

## 实现链

原赛前公开 v2 记录及其 evidenceBinding → 新建归档 prediction.frozenVersion → 首次正式赛果复盘行 → SQLite / PostgreSQL 历史载荷 → 历史列表 HTTP → 完整历史版本标签分组 → “按版本”页面选择。

`frozen-review-version-v1` 记录原公开记录哈希、证据/特征/模型对象哈希、原模型/策略标签、决策/记录/截止时钟和确切玩法/方向/盘口/SP，另带自身内容哈希。捕获必须通过原公开记录与赛事身份校验，并与原公开选择完全一致；不能从可变 predictionMeta 的当前模型版本取值。聚合再次与匹配赛事的原公开记录绑定核对，自行改标签后重算追溯哈希仍不被接受。

旧归档及已有复盘不补写缺失版本。重复记录中任一缺失或冲突版本证据时，该赛事结算保持在 UNKNOWN，而不是改归新模型或删除损失。已有结果计数与正式准入不变。0 SP 的模型参考保留其原始零值与版本，不变成官方赔率推荐。

完整分组版本为 `review-frozen-version-labels-v1`：模型/策略标签对作为组键；各组与 UNKNOWN 均有累计、逐日、HAD/HHAD/UNKNOWN 玩法子账。服务端压缩及前端选择器都检查累计、逐日、逐玩法交叉合计；不从分页列表统计。旧接口无分组仍显示未提供；新接口先让用户选组，不自动猜当前模型。“本版本”改名“按版本”，防止将累计当作当前版本业绩。

## 边界

- 这是冻结**标签**追溯，不是独立数据源真实性证明，也不是完整权重/参数修订身份。界面明确说明这一限制。
- 本批接通公开参考 v2 的已绑定记录；旧 v1、无证据绑定、正式/实时发布尚无相应版本链时保持未追溯，不能据此宣布所有轨道版本审计完成。
- 哈希源记录不存在、事件或选择不符时进入未知。该未知桶不改变总账分母。
- 独立前瞻、同决策配对赔率基准和冻结候选全集仍需原计划验证，不能以版本标签或样本区间代替。

## 验证

- verifyFrozenReviewVersion：真实公开捕获/归档/复盘；HAD/HHAD、0 SP、旧记录不补写、篡改与自重算、非法时钟、事件错配、重复冲突、分组合计与旧接口。
- verifyPredictionEvidenceRoundtrip：真实生成代、SQLite、PostgreSQL 投影及读端、两种主读 HTTP；使用隔离应用正常创建/兑换本地短期访问码，不关闭保护。管理员令牌单独访问历史仍应401。
- verifyEvidenceNativePostgres：隔离 PostgreSQL16，不安装服务，不使用生产数据。
- verifyReviewDashboard / verifyFullAppEvidenceBrowser：真实服务端分组输入、无默认版本、HHAD与HAD独立、UNKNOWN、三尺寸和键盘/原生选择器。
- verifyProductionReadiness 已加入冻结版本链强制验证。

本批不在 r696 中；必须随下一独立签名制品部署并验证运行时新增归档。不能靠旧历史回填制造线上已追溯样本。
