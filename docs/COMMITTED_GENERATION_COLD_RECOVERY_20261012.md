The authenticated r850 full package passed normal construction and Linux
dependency preparation. Its old-watcher pause restarted r844 before the new
runtime exchange. The old reader then failed with
`PUBLICATION_SQLITE_IDENTITY_MISMATCH`. Ordinary rollback also failed that
same startup check. PostgreSQL and both runtime markers remain the original
r844 identity. The unresolved recovery intent is retained.

This continuation admits only that exact terminal, pre-seed, code-only
transaction. It binds the signed original full archive, every pending recovery
file, the original database OID/schema, exact immutable generation pairing,
prepared source/dist hashes, absent API listener, and exact startup failure.
An active full controller, a healthy old API, a different recovery phase or
any unverified premise rejects it.

It stages the original authenticated FULL source and uses the normal candidate,
readonly database access, final database equality, archive, 900 second clock,
atomic complete application directory exchange, public and completion gates.
It changes no individual application source files, database rows, raw pointers,
model registrations, frozen recommendations or settlements.

Unavailable old-health and old-HTTP-mediated barriers are replaced by positive
stopped-worker, reclaimed old-service-cgroup and drained native auxiliary-writer
proofs before seed and final. The native seed/final protected PostgreSQL receipt
and immutable pointer locks remain. Candidate health is still mandatory.
The failed first attempt's lease/input/current files are retained. A separately
signed recovery attempt captures new actual readonly input and creates its own
900 second transition lease. It cannot extend the original authorization.

After the original source authorizations cease to cover a complete 900 second
attempt, a new independently signed coordinator may supply new authorization
documents. They are bound to the current pending intent, original full archive,
actual database/source pairing and new controller/engine Git source. The old
authorization files inside the original full package are never edited. The
coordinator explicitly delegates only those two authorization inputs; all
release modules are byte-verified original full source. The original native
coordination state is retained before recording new authorization hashes.
This does not change PostgreSQL metadata, business rows or application files.

The continuation runs under the same kernel release lock. On failure it retains
the original recovery material and invokes the fixed normal recovery helper.
Successful code recovery is followed by independent installed-source, public
TLS, frozen/ACK and natural synchronization verification. It is not proof that
a new database source batch has already been committed.
