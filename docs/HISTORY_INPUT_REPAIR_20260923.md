# 球队历史采集与模型输入修复

## 问题与改动

2026-09-23 只读审计发现 PostgreSQL 历史仓库正常更新，但下载清单缺少英甲 E2 和英乙 E3，六支球队没有仓库记录。旧签名训练产物虽然有相应英文球队，模型中文别名没有匹配；近期记录停在 2025-05-03，部分 Elo 为空或更陈旧。

本次沿用现有数据库与每 12 小时的 Worker 更新任务：

- 为米尔顿凯恩斯、克劳利、维冈竞技、布莱克浦、诺茨郡、格里姆斯比补精确一线队别名。青年、预备和女队不合并。
- 历史下载增加 E2/E3；定向补 2024/25、2025/26、2026/27 六个 CSV。首次本地收取约 1.18 MiB，得到 2,374 条有效赛果，六队各 99 场。
- Football-Data 空尾表头逐行兼容；非空匿名尾值拒绝并保留原始行哈希。本次有 1 条这样的异常行，不改原始 CSV。
- 新增 PostgreSQL 历史只读入口，为本次未开赛预测提供有界的历史赛果。赛果必须已完成导入且在预测前已实际获取；只接受明确的 90 分钟比分合同。
- Elo 与近期状态分别处理球队自己的种子时间，不能使用整个训练库的最晚日期过滤所有球队。过旧或不可核验的 Elo 种子不能冒充本次真实训练场数。
- 模型输出记录本场实际输入摘要；完整批次覆盖留在同步元数据中。新数据改变输入签名，触发未来预测更新；冻结记录和历史回测不使用新补的数据重写。

## 验证口径

1. 下载、CSV 解析、中文映射、90 分钟比分、去重和观察时间检查。
2. 隔离 PostgreSQL 中验证真实导入与模型读取，覆盖赛后获取的数据、不同来源、冲突和未知身份。
3. 发布前完整构建及当前提交 CI；发布后核对生效版本、正式采集周期和模型实际输入。
4. 本轮生产基线为 74 条推荐、8 个冻结串关，按精确 ID 和内容哈希复核，允许正常追加新记录。

“99 场已采集”不等于“99 场进入每项模型特征”。近期模型使用其配置的最近场数，Elo 使用有界历史重放与真实计数；每项采用数分别验收。窗口 Elo 的对手历史可能不完整，不宣称完整长期评级或命中率已提高。
