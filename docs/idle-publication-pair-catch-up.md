# 空闲页面进程自动跟进已提交的数据代际

## 现场与可复现缺陷

2026-09-07 20:21只读观察：服务缓存g-8e25…；PG和SQLite均为g-40e810…；当前发布指针g-e46c…、上一指针g-40e810…。刷新状态为publication-write-in-progress-serving-previous。20:19公开验收26/28，两个失败为健康/主读对齐。20:24采集收尾后恢复PG/SQLite/generation均43、健康和新鲜度正常。未重启正在执行的r699事务。

源码显示此前只有启动在previous-generation或HTTP发现指针变化后才注册重试计时器；健康active进程空闲时没有持续观察器。没有请求的提交间隙可能被错过，下一次请求又碰到后续写锁时，进程继续保留更旧一代。该控制流与现场一致，但并不把所有代际暂态都归因于这一缺陷。

## 修复

PostgreSQL主读已完成启动配对后，保持一个5秒轻量指针/SQLite身份观察计时器。状态不变时不创建完整resolver worker、不做完整档案读取；变化后仍走原来的后台解析、双库配对、指针令牌复核和读租约切换。写锁和pointer-commit锁仍阻止启动解析。失败、被新指针取代、previous代继续有界重试；正常完成后继续轻量观察，关闭服务时清理计时器。

没有放宽旧数据有效期、查询时效、来源准入、代际哈希或写锁保护；此补丁不能保证写事务执行期间完全没有过渡状态。

## 验证

真实Node服务和SQLite、PG身份查询替身的完整generation端到端102项通过。新增健康active启动→无后续HTTP请求→提交新双库身份→后台自动解析→新代际公开，以及健康未变化不多启动resolver的检查。旧WAL写锁、首次请求写锁、数据库不一致、错误查询、租约和原子切换检查保留通过。公开接口代际绑定11项、性能预热合同46项、定向ESLint通过。
