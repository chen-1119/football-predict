# 浅色 UI 与交互优化 · 2026-09-21

## 设计目标

统一使用浅灰页面、白色卡片、深色文字和绿色主操作。移除旧暗色渐变、装饰网格和互相覆盖的主题样式。胜平负用绿色、让球用蓝色辅助区分，玩法文字始终保留。

参考信息层级和模块组织，不复制图像或页面资产：

- [Football manager dashboard — Qubstudio](https://dribbble.com/shots/14416195-Football-manager-dashboard)
- [Sport Dashboard — Hadi Sharifani](https://dribbble.com/shots/15696161-Sport-Dashboard)

## 交互改动

- 推荐与复盘：队名、方向、SP、比分优先；概率分析与冻结证据默认折叠；版本统计与模型校准折叠。
- 复盘：按球队或比赛编号搜索，按结算状态筛选；初始显示 12 条，每次追加 12 条；汇总成绩始终使用全量分母，筛选不改变命中率。
- 赛程：球队、联赛或编号搜索，明确结果数量、清空与无结果状态；保留竞彩日跨午夜归属和返回列表状态。
- 导航：数据状态详情展开查看；账户菜单支持键盘、Escape、外部点击关闭；手机底部导航保留安全区。
- 详情与次级页面：统一浅色表面、文字对比和标题尺寸；详情导航滚动时保持可达。

## 数据边界

本次只更新前端展示与交互。保留官方／参考／影子状态、真实来源与时效、原始推荐冻结版本和结算口径；不修改概率算法，不产生新的正式推荐或改写历史命中率。没有有效数据时继续显示原因。

## 验证

- 194 项推荐、串关、报价、渲染时钟与 UI 交互测试通过。
- 本地浏览器使用只读线上快照，完成推荐空状态、复盘搜索与结算组合筛选、清空、12→24 条分页、赛程搜索、详情跳转和状态浮层检查。
- 窄屏实测 CSS 视口宽 434px，内容宽 426px，无横向溢出；卡片单列，底部导航可达。浏览器请求 390px 时实际提供 434px，因此不宣称已精确验证 390px。
- 发布前完整构建与 GitHub CI 必须通过；线上版本与资产哈希、API 和页面另行验收，不用本地截图代替上线证据。

## 发布方式

在现有 PostgreSQL-only 服务上仅更新前端源码和构建资产，最后切换 index.html。保留旧资源供已打开页面使用，5 个后端服务无需重启；版本签名、旧文件哈希和可恢复备份保留，不迁移或重复导出数据库。
