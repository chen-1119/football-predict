# 私有预测执行输入留存

## 本次补齐的真实链路

`syncData` 的私有 `prospectiveAuditMatches` 流在实际 `rebuildPublishedPredictionModel()` 调用处，通过 `predictionExecutionCapture.run()` 保留传入计算器的完整可支持对象、实际返回值、执行开始/结束时间、赛事身份、模型版本和内容哈希。公开输出重建不传入捕获器，冻结/已开赛的模型继续走原保护分支，不为旧记录补造新证据。计算器仍只调用一次，返回原对象；原异常仍向上传递，不吞掉或重试。

这不是原始上游文件归档，也没有捕获所有模块加载状态、环境依赖或签名来源时钟。它不自动成为公开方向证据、正式账本或晋级样本。`productionEligible=false`、`sourceVerified=false`，完整确定性重放仍需继续实现。

## 不丢失空值语义

初次测试发现普通 JSON 会丢掉模型中的显式 undefined。现采用 `json-with-explicit-undefined-v1`，保留 undefined 与 null、缺省属性的区别，提供配套 decode。输入/输出哈希绑定的是这个编码，不可用普通 JSON.parse 后不解码就直接声称原样重放。

对象标记冲突、稀疏数组、自定义对象/toJSON、函数、非有限数字等不能悄悄转成别的值；不支持时排除该捕获，原计算照常进行。敏感键及明显包含凭据参数的 URL 同样拒绝留存，不把值写到诊断错误里。此扫描不应被视为完整通用 DLP，需要继续保持输入数据中不携带秘密。

## 私有存储与容量保护

- 仅写 `DEFAULT_STORE_DIR/prediction-execution-captures/<内容哈希>.json.gz`，不放 public 数据目录，不附着到公开推荐对象。
- 独占写锁、内容命名、新建写入、fsync、解压回读校验；相同批次验证后复用，不覆盖已有批次。损坏、未知文件、目录链接、写锁占用、读写失败均返回明确诊断，不重试发布。
- 每侧编码上限 2 MiB，每批合计 16 MiB、128 条；私有目录最多 256 MiB 或 512 文件，任一达到即停止新增并报告容量不足。不会擅自删除旧捕获，主流程与历史账本不受影响。
- sync-meta 只增加计数、跳过原因、持久化状态和哈希，不暴露完整输入输出或文件系统路径。
- **这是有界初始存储，不是永久归档方案**。以每 5 分钟一批计算，512 文件上限约 42.7 小时；实际也可能先到字节上限。后续仍需按证据保留要求实施去重/长期容量策略，不能说长期前瞻留存已经完整解决。
