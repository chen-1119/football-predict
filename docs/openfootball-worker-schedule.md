# 社区补充源的服务器周期采集

2026-09-08。Q2 接续工作：把独立原始响应存储接入现有同步 worker 的慢阶段。本批代码不在已签名、排队中的 r704 中；通过测试或合并不代表线上已启用。

## 行为与边界

- 不新增服务器、云函数、收费 API、守护进程或定时器。后续部署成功后，复用现有服务器 worker，不需要本地电脑常开。
- 默认启用；`ENABLE_OPENFOOTBALL_OBSERVATIONS=0` 可关闭。五个固定社区源每次最多五次请求，沿用单源 20 秒、2 MiB、拒绝重定向的限制。
- 全部五源成功后至少间隔六小时，在随后一次可运行的慢阶段采集；不是精确六小时的独立 cron。失败按 30、60、120、240、360 分钟冷却，上限六小时；失败和冷却仍显示异常，不伪装为采集成功。
- 私有目录为现有服务数据目录下 `research/openfootball-current-observations-v1`。原始字节和首次接收记录沿用持久化 SQLite；调度状态另存 `schedule-attempt-YYYY-YY.json` 和 `sync-status.json`，不把调度时钟当作源证据。
- 使用真实目录检查、互斥锁、原子状态写入和 30 分钟未完成租约。中断向 worker 原样传播；状态写入失败不继续请求上游。UTC 七月切换赛季，不沿用旧赛季失败冷却。
- 每次调用带独立 requestId。命令退出零但未产生同一 requestId、当前完成时间、五源成功及有效接收链状态时，仍判失败。复用旧数据的发布流程不增加采集成功时钟。
- `communityReceiptStep` 单独进入 worker 慢阶段结果，不进入决定是否重建正式数据的 enrichmentSteps；仅保存研究响应不应触发正式数据重新生成。
- 最新失败/未完成尝试与上次完成结果分开报告。`collectionOk`、`latestAttemptState`、`lastCompletedCollectionOk` 不相互替代；“成功下载”也不等于比赛数据及时、映射有效或模型已采用。

正式模型采用、预测写入、官方结算写入均为零。来源保持未核验映射、非官方、研究专用；整份文件首次接收时间不得直接充当每一条赛果可用时间。此次没有新增公开页面卡片，状态先体现在 worker 步骤结果中。
