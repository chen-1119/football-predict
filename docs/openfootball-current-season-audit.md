# 免费当前赛季补充源：隔离核验，不是生产接入

## 本次实现

`npm.cmd run audit:openfootball-current -- 2026-27` 只读访问 OpenFootball
football.json 的五大联赛指定文件，逐源输出候选赛果、原始文件 SHA-256、
排除原因、逐球队原名覆盖、最新赛果日期和本次完整响应接收时间。
无写文件、仓库导入、模型调用、同步 worker 或部署依赖；输出为标准输出。
`npm.cmd run verify:openfootball-current` 为离线回归检查。

这不扩展既有葡甲历史补齐脚本的允许清单，也不修改已就绪球队强度。
固定来源域名与联赛清单，拒绝重定向，单源 20 秒、2 MiB 上限，顺序最多
5 请求且无自动重试。单源失败保留其他来源的核验结果，但整体 ok=false。
严格检查联赛名称、赛季、日历、整数比分和原始球队名称。重复同一对阵日期
的所有副本均隔离，包括有比分与无比分的冲突。不做模糊球队合并。
无全场比分的赛程不能视为 0:0；当天及未来日期的比分不进入候选集合。

## 不能据此宣称的事情

- 这是社区来源，不是官方结算依据；productionAdmittedRows 恒为 0。
- receivedAt 只标记本次接收，不是持久化 firstObservedAt、官方发布时间，
  更不能回填过去决策前的可用时间。resultObservedAt、kickoff 和
  upstreamPublishedAt 均保持 null，sourceVerified=false。
- 有球队原名不等于已核准 Sporttery/provider/联赛/赛季对应关系。
- 92 条不是全部近期赛果覆盖，不含赔率、伤停或阵容；最新日期不能代表
  每支球队均有足够近期样本，也不能直接证明赛事已完整更新。
- 文件生成时间不代表赛果及时性。项目说明 JSON 每日生成，但其上游
  Football.TXT 尚无自动日更保证。
- 这次一次性服务器读取不依赖本地采集代理，但尚未建立常驻云端采集通道。

来源与许可：[OpenFootball 项目说明](https://github.com/openfootball/football.json)
标示数据及脚本采用 CC0-1.0、无需 API key，并说明更新限制。

## 下一步接入门槛

1. 单独诊断英超失败并观察实际跨批次可用性，不降低现有主流程或发布门槛。
2. 核准逐球队、联赛和赛季身份，保留 B 队/女足/青年队区别；统计当前待预测
   对阵的真实覆盖，而不把全部 92 条笼统当成系统已补齐。
3. 新建内容绑定、只向前累积的接收记录；以真实可知时间参与未来影子评估，
   不回填旧推荐，也不替代官方赛果/赛前赔率证据。
4. 与可信赛果交叉检查冲突后，另行实现并验证明确的试验源接入和故障隔离。
   固定版本评估达标前不改变正式推荐状态。
