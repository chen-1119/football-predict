状态：本文件记录实现及验收范围，不代表版本已在线。实际上线仍以签名发布完成标记和线上核验为准。

## 本次实现

- 主服务器周期采集增加官方 result:1；复用已有响应规范化、Ed25519 签名和快通道包装。市场证据仍只有 current/calculator，结果不能替代市场数据。
- 结果请求失败或空返回时保留旧签名结果及原始时间，显式报告降级；上传成功不等于比分已发布。
- 修复刷新监听在“已完成 A → 错误 B → 恢复 A”时跳过真实重验的问题；保留锁、退避和失败关闭。
- 快通道轮询仅缓存已验证的摘要和时间，不常驻保存大快照；信任文件、内容、策略和时间边界变化重新核验。
- 健康检查区分探针新鲜度和发布器成功时间。旧探针、缺失探针及旧版缺少诊断字段均明确标为观察状态，不能冒充新鲜采集。
- PostgreSQL 主读模式的监控支持严格四字段 SQLite 配对；修复命令拆为直接 Node 子进程，共用总期限，隔离密钥、不在监控中执行 VACUUM。
- 发布前提前进行只读时间窗口探测，保留原有 127 分钟发布预算、后续候选验证和切换前再次校验。
- 提供普通 ubuntu 身份的一次性延迟发布任务，不安装 cron、不复制本地 SSH 私钥、不增加 root 入口。计划时间不是安全证明；到时重新验签并仅调用一次现有发布入口，由其读取最新赛程判断。失败不重放同一序号；普通断线后可继续，服务器重启或会话进程被清理不保证存活。
- 固定 QA 辅助脚本约束 LF 换行，避免 Linux 将 CR 误认为 shebang 解释器路径；只随正常签名发布安装，不临时改写线上 root 脚本。
