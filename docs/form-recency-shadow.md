# 近期状态时效：独立影子过滤与回执绑定复演

## 结论与限制（2026-09-08 北京时间）

发现真实输入缺陷：`formConfidence()` 按两队样本数计算置信度，`blendLambdasWithForm()` 未使用最近比赛日期限制其贡献。当前发布代中，赛事 `2041346` 的主队最后比赛为 `2025-05-11T12:00:00+01:00`，距离模型生成时间 `2026-09-07T06:18:18.819Z` 为 483.804 天；主客各 12 场样本仍产生 confidence=1、form weight=0.42。页面输入充分性已经有 240 天限制，但它与实际模型算术不一致。

本次仅增加可独立运行的研究规则和回执绑定复演工具，生产算术只新增函数导出，没有接入新过滤、改权重或改模型版本。它不能说明该缺陷导致了全部历史落后，也没有证明过滤后命中率提高。已发布方向、冻结归档、结算和正式账本均不改写。研究结果不得直接晋级或自动发布。

## 固定实验规则

- 版本 `form-recency-input-shadow-v1`：分别检查 training-history、500-recent-form 两个来源、两支球队的 lastMatchAt。
- 时钟必须是显式、带时区、日历合法的模型生成时间；不使用未来开球时间或当前系统时间代替原决策时间。
- 缺日期、非法日期、比赛发生在评估之后、任一球队超过 240 天：排除该来源，不移除另一个可用来源。
- 0–60 天标为 recent；超过 60 天且不超过 240 天保留为 aged-history。后者依然沿用原权重，**这不是完整的近期衰减优化，也不证明旧历史足够新鲜**。
- 240 天取自现有充分性口径，60 天是分类界线；均不是根据本批结果调参得到的最优值。
- 全部输出显式 productionEligible=false、nominationAllowed=false、sourceVerified=false。算术回执证明计算一致，不是来源独立认证或时钟外部见证。

## 为什么只复演一个计算阶段

实际发布行省略原始 formSnapshot。第一次把发布行直接送入完整 scorer，误将缺失输入当作无 form，生成零变化报告。该报告保留在私有 outputs 中，同时有 `.invalidated.json` 标记，不可用于结论。

修正后必须先校验原 model.inputUsage 的哈希、算术、事件和模型绑定、严格时间以及赛前生成条件。仅用保留的 model.form 重建 form 阶段输入，并要求 before/candidates/weight/output 与原回执逐项 JSON 完全一致，才运行固定影子过滤。无法精确复演的行排除，不放宽误差、不伪造原始输入、不生成新的公开方向。
