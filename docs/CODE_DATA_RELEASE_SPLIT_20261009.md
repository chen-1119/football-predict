# 代码、数据库与模型参数独立发布

## 原问题

原 `runtime-only` 发布仍为候选验证执行全库 dump、创建候选库、restore 与数据镜像。最终继续使用原生产库，但候选副本和长期保留的种子文件消耗磁盘。旧 `3 × databaseBytes` 是保守空间预算，不表示每次实际新建三个数据库。

## 新路径

| 变更 | 执行方式 | 数据边界 |
| --- | --- | --- |
| 代码、UI、兼容当前表结构的模型加载代码 | 自动选择 `code-only` | 复用生产库；不 dump、不创建候选库、不 restore、不镜像全库 |
| migration、存储实现或受保护的数据兼容契约变化 | 选择原 `database` 路径 | 保留隔离库、迁移验证和现有恢复流程 |
| 训练参数版本 | 独立注册命令及 CAS/不可变历史 | 代码发布保留现有参数；注册成功和未来采用另行验收 |

分类同时绑定已安装源码与候选源码的完整 migration 成员集、存储模块和迁移契约。缺失、未知文件或非法快照直接拒绝。代码路径还验证实际 PostgreSQL migration ledger 与 catalog hash，不能靠修改发布参数强制跳过迁移。

## 普通代码发布

1. 正常签名包、容量与窗口检查。预检只读观察，不预留空间。
2. 使用签名预构建 dist；安装依赖的隔离构建进程没有数据库凭据，禁用 npm 生命周期脚本。
3. 构建完成后，在现有有界同步屏障中暂停写入，复制当前不可变发布代际与现有模型文件。API 继续服务。
4. 创建短时候选账号，仅授予生产库 CONNECT、业务 schema USAGE、表 SELECT。默认只读只是附加限制；关闭默认只读后依然没有业务写权限。账号有效期 15 分钟。
5. 候选 API、原发布继承规则与数据一致性检查通过后，停止候选、撤销授权并删除候选账号。存在连接时拒绝删除，不强制终止。
6. 沿用同一生产库进行原子代码切换；保留原恢复事务、自然 worker、新发布数据和公开端验收。
7. 完成标记与恢复事务清除后，只清理本次精确 `code-seed-store` 临时快照，保留签名、状态、回执等证据。拒绝链接、跨挂载、异常属主和未完成恢复状态。清理失败保留快照并记录原因。

候选授权属于数据库目录元数据变更，不应称为完全零数据库写入；业务表记录不因此修改。失败恢复恢复服务及原代码，不用旧备份覆盖此后产生的业务数据。若账号撤销失败，仍执行服务恢复并保留失败证据。

## 容量

数据库路径原公式不变。代码路径去除 `3 × databaseBytes` 的 PostgreSQL 工作预算和另一个全库 dump 预算；保留四份发布代际文件的峰值预算、三份应用目录、2 GiB 构建余量，以及每设备至少 5 GiB 保留量。

2026-10-09 09:44:55 北京时间，固定 SSH 指纹的真实线上只读预检选择 `code-only`：所需 **15,807,861,013 bytes**，可用 **48,130,617,344 bytes**。该值是当时的保守准入预算，不是实测峰值、空间预留或未来保证。后续发布仍重新检查。

## 验证与状态

- 初版 22 项新单元测试，连同原容量测试共 38 项通过、0 跳过；权限修复新增同名函数体漂移反例，最终为 23 项新测试、39 项联合测试。
- 8 组实际 Bash 分支测试：代码/数据库成功路径，以及预构建、种子、账号、候选、最终断言和账号撤销失败；外部系统操作由 fixture 替代。
- Linux 独立临时 PostgreSQL 的真实权限验证：可读；即使关闭默认只读也无法增删改、清表、改表或取得生产角色；活动连接阻止账号撤销；撤销不改变原表数据。
- 同一隔离 Linux 测试验证快照清理：链接及恢复未结束被拒绝，完成后只删除目标快照、保留外部哨兵和证据。
- 原 360 项 mandatory 回归通过。第一次检查因原分支检查器要求的缩进边界失败，修复缩进后通过，原断言保留。

上述隔离测试不是生产切换证明。此文提交时新流程尚未在线部署；正式交付仍需新固定提交的构建、签名发布和真实 source/dist/PG/worker/公开端/冻结连续性验收。全仓历史 lint 失败未宣称修复。此变更也不表示新模型已注册、正式校准已通过或命中率提高。

## r814 首次实际部署与权限修复

r814 实际选择了 code-only，候选与生产 OID 同为 28598409，种子验证报告 databaseCopies=0、backup=null、mirror=null，没有 football.dump。发布在候选账号检查中发现既有 `football.wake_recommendation_workers()` 为 PUBLIC 可执行的 SECURITY DEFINER 触发器，随后正常恢复 r812，没有切换或改业务记录。

触发器函数不能因为不能普通 SELECT 调用就被忽略：候选角色可以在自己的临时表上挂载该函数，间接写入生产推荐时钟。修复只对**精确函数名、属主、返回类型、参数、search_path 及已审定义 SHA256**匹配的既有通知器收回 PUBLIC EXECUTE；生产属主仍可执行，既有触发器正常工作。未知函数或函数体变化仍拒绝。保留权限变更意向和完成回执；这是一项持久的、限定范围的权限收紧，代码回滚不重新授予不安全的公共权限，不改函数体或 migration 原件。

Linux 隔离 PG 新增真实验证：临时表挂载触发器和直接调用均因权限拒绝；生产属主更新仍推进通知时钟。表只读限制、会话退役和精确快照清理仍通过。r814 的失败包与原回执保留；修复需新提交和正常新签名包，不重试失败 SHA。
