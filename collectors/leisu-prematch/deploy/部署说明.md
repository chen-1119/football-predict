# 雷速赛前采集器：服务器部署准备

这是一份 v0.2 待执行的独立部署方案。本轮只开发代码并准备配套文件，没有在服务器安装、登录、迁移数据库或启动采集。必须先完成用户要求的网站优化及其发布工作，再安排本部署；安装脚本不探测、中断或接管现有发布。本方案只部署独立采集器及其专用数据存储。已提供网站读取模块，但尚未挂载网站真实 API；安装完成不等于网站已经使用雷速数据。

## 1. 部署边界与前提

- 使用运行 systemd、提供 `apt-get` 的 Debian/Ubuntu Linux 服务器；预先准备 Node.js >= 22.22.1、npm、sudo。安装脚本在创建用户或修改文件前拒绝旧版本。服务使用 `/usr/local/bin/node` 或 `/usr/bin/node`，不安装或替换网站的 Node.js。
- 新建独立用户 `leisu-collector`，无登录 shell；代码位于 `/opt/football-leisu-collector`，配置位于 `/etc/football-leisu-collector`，状态位于 `/var/lib/football-leisu-collector`。
- 代码由 root 管理；配置文件为 `root:leisu-collector`、权限 `0640`；状态及浏览器用户目录为 `0700`。浏览器登录会话属于敏感状态，不应放入 Git、普通备份包或公开网页目录。
- 安装仅复制 `package.json`、`package-lock.json`、`cli.cjs`、`scope.cjs`、`store.cjs`、`browser.cjs`、`mapping.cjs`、`runtime-policy.cjs`、`failure-policy.cjs`、`website-adapter.cjs`、`website-reader.cjs`、`schema.sql` 和临时登录辅助脚本 `login-ui.sh`。`team-aliases.example.json` 复制为全新专用配置目录中的 `team-aliases.json`；如有示例映射/配置，也复制到该目录。不会复制网站源码、测试报告、现有 `node_modules` 或生产环境文件。
- `npm ci --omit=dev --ignore-scripts` 只在独立包内运行，禁用项目和依赖的安装脚本。随后仅调用此包安装的 Playwright CLI 安装 Chromium。
- **安装会运行 `apt-get update`，安装 `xvfb`、`x11vnc`、`novnc`、`websockify`、`xauth`、`x11-utils`、`iproute2`、`fonts-noto-cjk`，并由 `playwright install --with-deps chromium` 安装或补齐浏览器系统库。这会影响服务器系统环境并占用网络、磁盘及安装时间。** 必须在网站优化完成后的合适维护时间执行。浏览器本体保存在专用状态目录；不会修改网站的 `node_modules`。安装这些包不会启动登录桌面，也不会打开防火墙端口。
- 必须事先具备对应数据使用授权及服务器正常访问条件。真实浏览器能打开页面，不代表服务器自动采集、保存和使用数据的权限已确定。

安装脚本只支持首次新安装。如专用用户、目录或同名 systemd 单元已经存在，会在写入前退出；不覆盖既有部署。中途失败保留已创建的专用状态，不自动删除，也不会启用定时器。

## 2. 网站优化完成后再安装

将完整 `server-ready` 包放到服务器独立暂存目录，检查内容后从该目录执行：

```bash
sudo bash deploy/install.sh --after-site-optimization
```

缺少 `--after-site-optimization` 将直接退出。该参数是操作者对执行时机的明确确认，不会自动判断网站优化是否完成。

脚本会安装文件并运行 `systemctl daemon-reload`，**不会运行 `login`、`migrate`、`collect-once`，不会 enable 或 start 任何单元**。默认 `LEISU_ENABLED=0`、`LEISU_ACCESS_VALIDATED=0`。

## 3. 配置最小权限数据库和赛事映射

使用专用配置文件写入真实连接，避免把含密码的数据库 URL 放进命令行、聊天、日志或 shell 历史：

```bash
sudoedit /etc/football-leisu-collector/collector.env
sudoedit /etc/football-leisu-collector/mappings.json
sudoedit /etc/football-leisu-collector/team-aliases.json
sudo chown root:leisu-collector /etc/football-leisu-collector/collector.env /etc/football-leisu-collector/mappings.json /etc/football-leisu-collector/team-aliases.json
sudo chmod 0640 /etc/football-leisu-collector/collector.env /etc/football-leisu-collector/mappings.json /etc/football-leisu-collector/team-aliases.json
```

- `LEISU_FIXTURE_DATABASE_URL`：使用仅能读取网站所需赛事数据的独立数据库角色；不能复用网站全权限生产连接。
- `LEISU_DATABASE_URL`：使用仅能操作 `leisu_prematch` 专用 schema 的独立角色。若需要管理员预建 schema 和权限，应由数据库维护者单独完成；不能为方便迁移授予网站业务表写权限或全库所有权。
- `LEISU_MAPPINGS_FILE`：保存经核实的人工赛事映射，格式以随包 `mappings.example.json` 和 CLI 校验为准。使用自动发现时可保留空数组 `[]`，但必须在登录后执行 `discover` 并检查结果，不能填入假比赛 ID。人工映射优先于同一网站赛事的自动映射。
- `LEISU_LEAGUE_URLS_JSON`：自动发现只访问此数组内已核实的官方联赛页。默认 `https://www.leisu.com/data/zuqiu/comp-82` 已由本地 `validation/leisu-league-samples.json` 的真实浏览器采样核实为英超资料页；此默认范围只有英超，不代表其他联赛已经覆盖。需要新增联赛时先核实实际官方 URL，再编辑此 JSON 数组。
- `LEISU_TEAM_ALIASES_FILE`：显式维护“雷速球队名 → 本网站球队名”的 JSON 对象。空对象 `{}` 表示只接受原名精确匹配；只加入经过核实的别名，不以模糊字符串或猜测填补冲突。
- `LEISU_FIXTURE_MAX_AGE_MINUTES=60`：维持赛事输入时效要求；不要为通过检查而把旧数据当成新数据。
- `LEISU_MAX_PAGES_PER_RUN=12`：每轮最多启动 12 次页面访问；有效配置范围为整数 1–100。到达预算后停止启动新页面，未处理任务交给后续正常计划。
- `LEISU_MAX_RUN_SECONDS=480`：每轮运行预算默认 480 秒；有效配置范围为整数 60–480。预算由 `runtime-policy.cjs` 控制，到期停止新页面与新导出批次。已开始的数据库事务仍需完成或回滚，单次查询有 30 秒超时；因此不能保证进程恰好在第 480 秒退出，进程另受 systemd 的 10 分钟超时约束。
- 两个开关先保持 `0`；`LEISU_HEADLESS=true` 用于之后正常后台运行。

环境文件采用 systemd `EnvironmentFile` 语法，无 `export`、命令替换或 shell 变量插值。不要加载足球网站整份生产 `.env`。示例中的空数据库值是未配置状态，不是可用凭据。

## 4. 用专用用户运行检查和初始化

以下辅助函数在服务器管理员的 Bash 终端中定义。它通过 systemd 加载专用环境文件，实际 Node 进程以 `leisu-collector` 运行，不把数据库密码写进命令行。

```bash
leisu_run() {
  sudo systemd-run --quiet --wait --pipe --collect \
    --uid=leisu-collector --gid=leisu-collector \
    --working-directory=/opt/football-leisu-collector \
    --property=EnvironmentFile=/etc/football-leisu-collector/collector.env \
    --property=UMask=0077 \
    --property=NoNewPrivileges=yes \
    --setenv=PATH=/usr/local/bin:/usr/bin:/bin \
    /usr/bin/env node /opt/football-leisu-collector/cli.cjs "$@"
}

leisu_run doctor
leisu_run migrate
```

先审查 `doctor` 结果和数据库角色权限，再执行 `migrate`。`migrate` 是显式写入专用 schema 的步骤；安装脚本不替你执行。后续登录完成并执行 `discover` 后，再用 `plan` 核对已映射赛事、输入时效和当前待处理计划。不要在页面登录或访问验证仍未完成时把开关设为 `1`。

## 5. 首次服务器登录和正常页面验证

本包已提供临时受控桌面脚本，不再要求服务器预先部署桌面。脚本通过临时 systemd 单元，以 `leisu-collector` 用户启动 Xvfb、x11vnc、websockify/noVNC 和浏览器：

- 使用专用显示号 `:92`，禁用 X11 TCP；Xauthority 随机凭据保存在临时私有目录中，不通过命令行或日志传递。
- VNC 只监听 `127.0.0.1:5902`，noVNC 只监听 `127.0.0.1:6082`；启动前检查占用，启动后复核监听地址。占用时直接退出，不终止别人的进程或删除显示锁。
- 只通过已认证的 SSH 本地隧道访问，不开公网端口、不修改防火墙、不提供公网 VNC。VNC 本身不再设置第二个密码，因此仅适用于可信服务器本地账户、可信操作电脑及已授权的 SSH 用户；不要把本机转发端口共享给其他人。
- 脚本只终止自己启动的 PID；专用临时单元对其子进程作最终清理，不使用 `killall` 或 `pkill`。永久浏览器目录 `/var/lib/football-leisu-collector/browser` 始终保留。

网站优化和安装完成后，在服务器 SSH 终端启动并保持该终端打开：

```bash
sudo /opt/football-leisu-collector/login-ui.sh
```

等待输出 `Ready`。在自己 Windows 电脑的另一个 PowerShell 终端建立隧道，输入实际 SSH Host 别名或 `用户名@服务器地址`，使用已有 SSH 认证，不把账号密码填入命令参数：

```powershell
$leisuSshTarget = Read-Host '实际 SSH 目标（已有 Host 别名或用户名@服务器地址）'
if ([string]::IsNullOrWhiteSpace($leisuSshTarget)) { throw 'SSH 目标不能为空' }
ssh.exe -N -o ExitOnForwardFailure=yes -L 127.0.0.1:6082:127.0.0.1:6082 $leisuSshTarget
```

保持隧道终端打开，在本机浏览器访问 [临时登录桌面](http://127.0.0.1:6082/vnc.html)，点击连接。不要使用 `-g`、`0.0.0.0`、公网反向代理或端口映射；若 SSH 服务器策略禁止 TCP 转发，需由服务器管理员明确允许这条本地转发后才能使用，不会自动修改 SSH 设置。

该临时单元加载专用环境文件，在工作进程中设置 `LEISU_HEADLESS=0`；后台服务配置不变。脚本会拒绝与正在运行的采集器或采集锁并用浏览器目录。重新登录前应先暂停本采集器定时器，并等待当前任务完成。

用户在受控浏览器中完成雷速官方正常登录及必要验证。电脑上已登录的浏览器不代表服务器浏览器已登录。检查真实目标赛事页面、赔率页、阵容与数据是否正常可见；若遇到访问阻断、验证码或权限提示，停止采集并按官方流程处理，不绕过。登录完成后关闭远程 Chromium 窗口（也可在远程浏览器内按 `Ctrl+Shift+W`），脚本会关闭整个临时桌面。关闭本机 noVNC 网页并不等于关闭远程浏览器；需要中止时在启动脚本的服务器终端按 `Ctrl+C`。临时单元最长运行 1 小时，结束后再关闭 SSH 隧道终端。

正常关闭会保留浏览器 profile 并释放 CLI 锁；CLI 对 `SIGTERM` 和 `SIGINT` 会尝试优雅关闭浏览器。硬杀或其他异常终止后若仍提示锁存在，检查锁记录的 PID 和临时单元状态再处理；脚本不会删除不明锁或现存浏览器目录。

服务器正常登录完成后，使用上面加载专用环境文件的函数，按顺序运行：

```bash
leisu_run discover
leisu_run plan
leisu_run probe
```

`leisu_run discover` 实际以专用用户执行 `node /opt/football-leisu-collector/cli.cjs discover`。它读取白名单联赛页已经渲染的 DOM，将主队、客队（含显式别名转换）与开赛时刻全部精确一致的赛事写入 `/var/lib/football-leisu-collector/auto-mappings.json`；冲突和未匹配赛事单独返回，不强行配对。先复核匹配数、未匹配项和冲突，再检查 `plan`。`probe` 单独验证服务器无头浏览器对已映射的今天/明天目标赛事是否能读取所需页面；没有当前可验证赛事或没有可用证据时，不能据此启用采集。

正式运行时，采集器会在自动映射尚不存在、缓存超过 6 小时或北京时间跨日后的下一次运行中重新读取已配置联赛 DOM，为每天新增的当前范围赛事建立精确映射，不依赖永久手填每日比赛 ID。新比赛不会保证出现后立即进入映射；需要及时复核时可手动执行 `leisu_run discover`。仅覆盖白名单页面实际提供且与网站赛事精确匹配的数据。

确认服务器本身正常访问及授权条件后，再通过 `sudoedit` 将 `LEISU_ACCESS_VALIDATED=1`、`LEISU_ENABLED=1` 写入专用环境文件。单次运行和导出复核：

```bash
leisu_run doctor
leisu_run plan
leisu_run collect-once
leisu_run export
```

检查实际证据、数据时间及异常说明；默认输出为 `/var/lib/football-leisu-collector/latest-evidence.json`。没有拿到所需字段时保留缺失状态，不用占位值伪装成采集成功。

导出通过数据库批量读取证据，每批最多 500 场，超过时分批处理。此上限是数据库读取批大小，与浏览器每轮 12 页的预算分别生效；不表示一次抓取 500 场。

若导出途中收到中断信号或耗尽时间预算，不开始下一批，也不发布部分结果或刷新导出时间；保留上一份完整导出，其过期状态仍由网站读取层判断。

## 6. 验证后显式启用定时器

只有网站优化完成、服务器正常访问验证通过、数据库及单次采集复核完成，才执行：

```bash
sudo systemctl enable --now leisu-prematch.timer
sudo systemctl list-timers leisu-prematch.timer --all
sudo systemctl status leisu-prematch.service leisu-prematch.timer --no-pager
sudo journalctl -u leisu-prematch.service -n 80 --no-pager
```

定时器每 5 分钟唤醒一次计划器，并带最多 30 秒随机延迟；**不是每 5 分钟抓取全部页面**。具体哪些比赛和时间点需要处理由 CLI 计划决定。systemd 同一 oneshot 服务仍在运行时不会并发启动第二个实例；单次任务超时上限 10 分钟。停机期间错过的唤醒不会集中补跑。

伤停维持北京时间每 6 小时一个采集时段。阵容正常在赛前 90、60、30 分钟核对，较早取得完整名单仍保留后续正常阶段，以检查临场变化。只有同场、同一开赛版本的 30 分钟阶段返回 `source_empty`（名单未公布），才允许 20、10 分钟各补查一次；20 分钟补查取得 `available` 后停止 10 分钟补查。错过阶段时只执行最新已到期阶段，不集中补跑；开赛立即停止。阵容任务优先，其后按开赛时间处理；页面和运行时间预算同时限制整轮任务。

`failure-policy.cjs` 只对明确识别的临时网络错误或服务端 5xx 响应允许有限自动重试：同阶段最多两次实际尝试、相隔至少 10 分钟。403/405、登录失效、结构解析失败、身份不一致等情况继续暂停，需人工检查并恢复；不能用重试掩盖访问阻断或错误数据。`doctor` 会明确报告熔断状态，CLI 遇到暂停时返回非零退出码 2。

联赛发现也使用该异常分类。每个配置联赛在同一北京时间日期、同一配置且不超过 6 小时的发现进度内最多尝试两次，失败后至少等 10 分钟；失败时间、HTTP 状态及原因保存在 `discovery-progress.json`。退避期间不为该任务开启浏览器，正常伤停/阵容任务仍可继续；发现页面未全部完成时不发布部分对应表。

服务使用非 root 用户、`NoNewPrivileges`、只读系统文件视图和专用状态目录写入限制。修改状态路径时必须同时调整服务的 `ReadWritePaths`，并重新评估权限；登录辅助脚本只支持本说明的默认专用状态与 profile 路径。首次远程桌面登录使用上面的临时单元，正式定时服务不依赖图形桌面。

## 7. 暂停与后续维护

```bash
sudo systemctl disable --now leisu-prematch.timer
```

这会停止后续唤醒；已在执行的采集可等待完成。确需立即中止本采集器时，单独执行 `sudo systemctl stop leisu-prematch.service`，不要操作足球网站服务。随后可将 `LEISU_ENABLED=0` 保存到专用环境文件。

不要把首次安装脚本当作更新或卸载脚本重复执行。后续升级需另行准备备份、版本切换及回退步骤；本方案不删除状态、浏览器登录记录或数据库数据。禁止对足球工作目录或共享目录执行递归 `chown`、清理或重装。

## 8. 后续网站读取接入

`website-reader.cjs` 提供两个可复用入口，当前只是模块，默认未挂载任何网站路由，也不监听端口：

- `createWebsiteReader({ exportPath, readFixture, ... })` 返回按本站比赛 ID 读取证据的函数。`exportPath` 必须是操作者配置的固定绝对路径，不能来自请求参数；留空时返回 `disabled`，不读取文件或赛事。`readFixture` 由网站显式提供，读取本站当前比赛，以便再次核对身份、开赛版本和比赛状态。
- `createWebsiteHandler({ exportPath, readFixture, authorize, ... })` 可接入网站现有受认证路由。必须显式提供 `authorize`，只有其返回布尔值 `true` 才允许读取赛事和文件；仅处理 GET/HEAD，请求或查询参数不能改变导出路径。模块使用私有、禁止缓存的 JSON 响应，不自建登录系统。

公开返回保留本站比赛 ID、开赛版本、状态、更新时间、有效数据观测时间和最近尝试时间。伤停与阵容保留可读内容；采集站网址、provider ID、球员来源 ID、内部任务键和文件路径不进入公开 DTO。较新失败或未公布状态与旧有效数据分别表示，不把旧数据的观测时间刷新成新时间。`predictionEligible` 始终为 `false`；过期导出、已开赛或改期冲突的数据不作为可用证据返回。

后续接入仍须在网站代码中挂载真实路由，并单独安排导出文件交付和最小只读权限，再验证实际鉴权、页面展示与错误响应。安装脚本不会修改网站服务、开放公开端口，也不会授予网站进程读取采集器浏览器 profile 或数据库写入的权限。目前未声称已接通网站真实 API。
